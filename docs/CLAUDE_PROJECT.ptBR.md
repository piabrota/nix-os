# Um projeto do Claude para o seu fork do nix-os

[English](CLAUDE_PROJECT.md)

Esta página mostra como montar no claude.ai um Claude Project que trabalha no seu fork do nix-os.
O projeto abre pull requests no fork, e o merge em `main` faz o deploy na sua VPS, como no
nix-os. Cada bloco de código é para copiar inteiro no campo que a linha acima dele indica.

Os passos que só você pode fazer (no claude.ai, no GitHub ou na Hostinger) estão marcados como
**manual**. Uma sessão do Claude não cria um projeto, não adiciona um repositório a um projeto e
não conecta uma conta.

> **Para quem é este arquivo.** Para uma pessoa que monta ou restaura um Claude Project. Um agente
> que trabalha neste repositório com o Claude Code CLI não lê este arquivo e não segue o que ele
> diz. As regras para mudar o repositório estão no [`AGENTS.md`](../AGENTS.md). Quando os dois
> arquivos discordam, o `AGENTS.md` vale.

Lido em **2026-10-29**, a partir do projeto que trabalha no `piabrota/nix-os`.

## 0. Antes: a sua VPS e o seu fork

1. **Manual.** Siga o [`FORK.ptBR.md`](FORK.ptBR.md) até o fim: o fork, a VPS NixOS na
   Hostinger, a chave de deploy, os três secrets do environment `prod` e o primeiro deploy. O
   projeto do Claude não faz nenhum desses passos e não precisa dos secrets.

## 1. Monte o projeto

1. **Manual, claude.ai.** Conecte o GitHub em https://claude.ai/connect-github. Depois instale o
   Claude GitHub App no seu fork (https://github.com/apps/claude/installations/select_target).
   Uma sessão só faz push onde a sua conta do GitHub faz push.
2. **Manual, claude.ai.** Crie um projeto privado. Sugestão:

   | Campo | Valor |
   |---|---|
   | **Nome** | nix-os |
   | **Tema** | a URL que a sua VPS serve, ou "a minha VPS NixOS" |

3. **Manual, claude.ai.** Em **Project settings > Repositories**, adicione:

   | Repositório | Para quê |
   |---|---|
   | `https://github.com/<your-user>/nix-os` | o seu fork: o projeto trabalha nele |
   | `https://github.com/h0ffmann/ptbr-writer` | a skill `bipr`, que escreve os PRs (só leitura) |

   Não adicione `piabrota/nix-os`, a menos que você também contribua com ele. Uma sessão não
   alcança um repositório que o projeto não lista.

4. **Manual, claude.ai.** Em **Project settings > Instructions**, cole o bloco do §2.
5. **Manual, claude.ai.** Em **Project settings > Cloud environment**, escolha ou crie um
   ambiente (§3).
6. **Manual, claude.ai.** Escolha o modelo padrão. A memória é opcional; as tarefas podem ficar
   desligadas.

## 2. As instruções do projeto

Troque `<your-user>` pelo seu usuário do GitHub e cole o bloco:

```text
This project works on <your-user>/nix-os, a fork of piabrota/nix-os: the NixOS configuration of one small, live Hostinger VPS. Read its AGENTS.md before you change anything; AGENTS.md wins over anything a thread assumes.

Hard rule: an agent never deploys. Never run `just deploy`, `nixos-rebuild` or `deploy` against the VPS, and never ask for the DEPLOY_* secrets. A merge to main is the deploy; open a PR and let a human merge it.

Hard rule: never remove or weaken a setting that AGENTS.md lists in "Do not break the machine" (the QEMU guest agent, cloud-init, OpenSSH and its key, GRUB on /dev/sda, the deploy user, magicRollback). Never change system.stateVersion.

Hard rule: every change is judged by its cost. Build the old and the new system, compare them with `nix run nixpkgs#dix`, and put the size difference in the PR. No GUI, no fonts, no heavy runtimes, no new resident daemon without a reason.

Hard rule: every justfile must run on the stock `just` that Ubuntu 24.04 LTS ships through apt (1.21.0). Don't use newer syntax such as `[group]` or `[positional-arguments]`.

Hard rule: never commit a secret, a private key or an .age file.

Hard rule: name branches claude/nix-os-<goal-slug> (for example claude/nix-os-gitops-deploys), never with a thread or session id such as claude/project-thread-wchbf1.

Hard rule: write every PR with the bipr skill from h0ffmann/ptbr-writer: the title in pt-BR, the body in pt-BR first and its English mirror after `---`, without the skill's footer. Commit messages stay in English.

Hard rule: never leave an agent or tool trail in commits, PRs, issues, comments or files: no Co-Authored-By trailer, no "Generated with" or "Generated by" line, no claude.ai/code session links, no link to a project thread. If a tool adds such a line by itself (the GitHub connector adds "Generated with Claude Code" to a new PR), edit the PR and remove it. Check the final body before you publish it.
```

As regras vêm do `AGENTS.md` do nix-os e das instruções do projeto que trabalha no
`piabrota/nix-os`. Se você mudar uma regra no `AGENTS.md` do seu fork, mude também este bloco.

## 3. O ambiente na nuvem

Uma sessão não lê o script de setup, as variáveis nem os secrets de um ambiente, então este
arquivo não os registra. O ambiente não precisa de nenhum secret: o deploy roda no GitHub
Actions, com os secrets do environment `prod`.

Em 2026-10-29, uma sessão encontrou Ubuntu 24.04, `nix` 2.34, `gh`, `python3` e `cargo`. Faltavam
`just` e `shellcheck`. Para rodar o `just check` numa sessão, ponha no script de setup:

```bash
#!/usr/bin/env bash
set -euo pipefail
sudo apt-get update -qq
sudo apt-get install -y -qq just shellcheck
```

⚠ Esse script não rodou numa sessão. O `apt` do Ubuntu 24.04 instala o `just` 1.21.0, a versão
que as regras pedem.

## 4. Conectores e rotinas

- **Conectores.** O projeto não precisa de nenhum.
- **Rotinas.** O projeto não tem nenhuma.

## 5. O que fica de fora

- a memória do projeto, os chats e os artefatos;
- o script de setup, as variáveis e os secrets do ambiente;
- os secrets do GitHub (`DEPLOY_SSH_KEY`, `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`);
- ids de modelo, de conta, de sessão e de rotina, e endereços de e-mail.

## 6. Como manter atualizado

Quando uma configuração do projeto muda, leia o valor de novo no claude.ai e mude este arquivo e
o [`CLAUDE_PROJECT.md`](CLAUDE_PROJECT.md) no mesmo PR, com a data nova no topo.
