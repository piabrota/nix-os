# A Claude project for your nix-os fork

[Português](CLAUDE_PROJECT.ptBR.md)

This page tells how to set up a Claude Project on claude.ai that works on your fork of nix-os.
The project opens pull requests on the fork, and a merge to `main` deploys to your VPS, as in
nix-os. Copy each code block whole into the field that the line above it names.

The steps that only you can do (on claude.ai, GitHub or Hostinger) have the mark **manual**. A
Claude session cannot create a project, add a repository to a project or connect an account.

> **Who this file is for.** A person who sets up or restores a Claude Project. An agent that works
> in this repository with the Claude Code CLI does not read this file and does not follow it. The
> rules for changes to the repository are in [`AGENTS.md`](../AGENTS.md). Where the two files
> disagree, `AGENTS.md` wins.

Read on **2026-10-29**, from the project that works on `piabrota/nix-os`.

## 0. First: your VPS and your fork

1. **Manual.** Do all of [`FORK.md`](FORK.md): the fork, the NixOS VPS on Hostinger, the deploy
   key, the three secrets of the `prod` environment and the first deploy. The Claude project does
   none of these steps and does not need the secrets.

## 1. Set up the project

1. **Manual, claude.ai.** Connect GitHub at https://claude.ai/connect-github. Then install the
   Claude GitHub App on your fork (https://github.com/apps/claude/installations/select_target).
   A session can push only where your GitHub account can push.
2. **Manual, claude.ai.** Create a private project. Suggestion:

   | Field | Value |
   |---|---|
   | **Name** | nix-os |
   | **Topic** | the URL that your VPS serves, or "my NixOS VPS" |

3. **Manual, claude.ai.** In **Project settings > Repositories**, add:

   | Repository | What for |
   |---|---|
   | `https://github.com/<your-user>/nix-os` | your fork: the project works on it |
   | `https://github.com/h0ffmann/ptbr-writer` | the `bipr` skill, which writes the PRs (read only) |

   Do not add `piabrota/nix-os` unless you also contribute to it. A session cannot reach a
   repository that the project does not list.

4. **Manual, claude.ai.** In **Project settings > Instructions**, paste the block of §2.
5. **Manual, claude.ai.** In **Project settings > Cloud environment**, select or create an
   environment (§3).
6. **Manual, claude.ai.** Select the default model. Memory is optional; tasks can stay off.

## 2. The project instructions

Replace `<your-user>` with your GitHub user and paste the block:

```text
This project works on <your-user>/nix-os, a fork of piabrota/nix-os: the NixOS configuration of one small, live Hostinger VPS. Read its AGENTS.md before you change anything; AGENTS.md wins over anything a thread assumes.

Hard rule: an agent never deploys. Never run `just deploy`, `nixos-rebuild` or `deploy` against the VPS, and never ask for the DEPLOY_* secrets. A merge to main is the deploy; open a PR and let a human merge it.

Hard rule: never remove or weaken a setting that AGENTS.md lists in "Do not break the machine" (the QEMU guest agent, cloud-init, OpenSSH and its key, GRUB on /dev/sda, the deploy user, magicRollback). Never change system.stateVersion.

Hard rule: every change is judged by its cost. Build the old and the new system, compare them with `nix run nixpkgs#dix`, and put the size difference in the PR. No GUI, no fonts, no heavy runtimes, no new resident daemon without a reason.

Hard rule: every justfile must run on the stock `just` that Ubuntu 24.04 LTS ships through apt (1.21.0). Don't use newer syntax such as `[group]` or `[positional-arguments]`.

Hard rule: never commit a secret, a private key or an .age file.

Hard rule: name branches claude/nix-os-<goal-slug> (for example claude/nix-os-gitops-deploys), never with a thread or session id such as claude/project-thread-wchbf1.

Hard rule: write every PR with the bipr skill from h0ffmann/ptbr-writer: the title in pt-BR, the body in pt-BR first and its English mirror after `---`, without the skill's footer. Commit messages stay in English.

Hard rule: never leave an agent or tool trail in commits, PRs, issues, comments or files: no Co-Authored-By trailer, no "Generated with" or "Generated by" line, no claude.ai/code session links, no link to a project thread. If a tool adds such a line by itself (the GitHub connector adds "Generated with Claude Code" to a new PR), edit the PR and remove it. Check the final body before you publish it.
```

The rules come from nix-os's `AGENTS.md` and from the instructions of the project that works on
`piabrota/nix-os`. If you change a rule in your fork's `AGENTS.md`, change this block too.

## 3. The cloud environment

A session cannot read the setup script, the variables or the secrets of an environment, so this
file does not record them. The environment needs no secret: the deploy runs on GitHub Actions,
with the secrets of the `prod` environment.

On 2026-10-29, a session found Ubuntu 24.04, `nix` 2.34, `gh`, `python3` and `cargo`. `just` and
`shellcheck` were missing. To run `just check` in a session, put this in the setup script:

```bash
#!/usr/bin/env bash
set -euo pipefail
sudo apt-get update -qq
sudo apt-get install -y -qq just shellcheck
```

⚠ This script has not run in a session. Ubuntu 24.04's `apt` installs `just` 1.21.0, the version
that the rules ask for.

## 4. Connectors and routines

- **Connectors.** The project needs none.
- **Routines.** The project has none.

## 5. What stays out

- the project's memory, chats and artifacts;
- the environment's setup script, variables and secrets;
- the GitHub secrets (`DEPLOY_SSH_KEY`, `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`);
- model, account, session and routine ids, and e-mail addresses.

## 6. Keeping it current

When a project setting changes, read the value again on claude.ai and change this file and
[`CLAUDE_PROJECT.ptBR.md`](CLAUDE_PROJECT.ptBR.md) in the same PR, with the new date at the top.
